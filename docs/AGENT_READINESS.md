# 설계 도우미 AI의 현재 완성도와 남은 작업

기준일: 2026-09-21. 현재 상태는 **로컬에서 통합 실행하고 핵심 계약을 검증한 단계**다. 프로젝트 저장·계산·변경안·부품 조회의 실행 구조는 구현했지만, 실제 사용자 계정과 정상 응답하는 외부 LLM을 연결한 전체 사용자 흐름은 아직 완료 검증하지 않았다. 이 문서는 운영 준비 완료를 선언하지 않는다.

배포·설정은 [FastAPI 실행 안내](FASTAPI_MIGRATION.md), 코드 위치는 [구조 안내](ARCHITECTURE.md), 학습 모델의 평가·재현 한계는 [ML 안내](../ml/README.md)를 따른다. 이전 [에이전트 명세](AGENT_SPEC.md)의 D1·Better Auth 설명은 이전 구조의 기록이며, 현재 실행 코드는 `backend/app`이다.

## 1. 성능 모델과 대화 에이전트는 별개다

| 구분 | 현재 동작 | 제한 |
| --- | --- | --- |
| 원본 성능 | AircraftVerse 시뮬레이션 KPI·trim 조회 | 실제 제작·비행 측정값이 아님 |
| 편집 요약 KPI·후보 개선 | Neighbor Estimate와 제한된 후보·치수 탐색 | 새 best 모델로 최적화 점수를 대체한 것이 아님 |
| 로컬 best MLP | FastAPI CPU에서 속도별 항력·양력·추력·피치·전력·전류·비행시간·거리 예측 | 원본 시뮬레이션 앵커에 조건화됨. 질량·최대속도·비행 유효성은 미지원 |
| 설계 도우미 | OpenAI로 목표 해석·근거 설명, 서버가 허용한 계산·조회 도구 실행 | 외부 API 계정의 이용 가능 상태가 필요함. 임의 코드·자율 구매·무제한 도구 실행은 제공하지 않음 |

로컬 모델은 OpenAI를 호출하지 않는다. 설계 #17297의 실제 예측과 동체 길이 편집에 따른 갱신은 확인했다. 유효 원본 호버 입력이 없는 #20015는 `422 model_input_unavailable`로 거절한다. 모델 미반영 편집값·미지 범주·학습 속도 범위 밖 입력은 별도로 표시하며, 모델이 지원하지 않는 항목에 성능 향상이나 비행 가능성을 부여하면 안 된다.

## 2. 구현과 검증 증거

| 영역 | 구현된 계약 | 확인한 범위와 남은 경계 |
| --- | --- | --- |
| 로그인 | Google OIDC·PKCE, 일회성 state, 서버 세션, 기존 Google subject와 사용자 ID 매핑 | 서명·nonce·audience·만료·state 재사용 거절을 합성 테스트로 확인. 실제 Google 계정 입력 화면 진입까지 확인했고 계정 인증 완료는 별도 |
| 개인 저장 | PostgreSQL에 프로젝트·revision·실행·견적 저장, 모든 개인 API의 소유권 검사 | 실제 PostgreSQL에서 사용자 격리·revision 경쟁·실패 rollback 확인. API 테스트 로그인은 합성 세션을 사용 |
| 변경안 | 서버가 계산한 후보·허용된 치수 변경만 제안, 사용자가 적용해야 반영 | 적용·중복 적용 거절·오래된 revision 거절·과거 revision 복구 확인. 실사용 목표에 대한 추천 품질 평가는 남음 |
| 실행 | `start/progress/result/error` NDJSON, 기록 조회, 취소, 부분 결과 보존 | API 취소와 DB 최종 상태, 프록시 청크 전달·요청 중단을 테스트. 실제 브라우저·nginx·외부 지연을 함께 건 장시간 장애 시험은 남음 |
| 한도 | KST 기준 사용자 20회/일·전체 200회/일, 사용자 동시 실행 1개, 실행당 LLM/도구/공급자 4/20/40회 | PostgreSQL 병렬 경쟁과 정확한 lease 만료 경계 검증. 호출 횟수 제한은 금액 기준 과금 상한이 아님 |
| 답변 근거 | 현재 revision·fingerprint, 원본 데이터·편집 추정·학습 모델·문서·상품 출처를 근거 카드로 분리 | 실제 모델 출력을 Q&A 근거에 넣는 통합 테스트 통과. 이 테스트의 LLM 응답은 mock이며 답변의 사실 정확도를 입증하지 않음 |
| OpenAI | 구조화된 목표·답변, 30초 공급자 timeout, 자동 재시도 없음, 공급자 오류 비밀값 제거 | 마지막 실제 `gpt-5-mini` 의도 분석 1회는 HTTP 429 `credit_balance_exhausted`. 정상 외부 응답을 받은 전체 에이전트 흐름은 미검증 |
| AliExpress | 서버 BOM에 대한 검색·상세·링크 조회, 원본 offer에 묶인 견적 선택·저장 | 실제 일반 모터 검색 8개 상품 반환, 특정 KDE 모터의 빈 결과를 `not_found`로 확인. 전체 설계 BOM의 구매 가능한 SKU와 저장 견적을 실계정으로 끝까지 검증한 것은 아님 |
| 이전 | D1 export의 사용자·소유권·ID·JSON을 PostgreSQL에 일괄 import, 기존 대상 보호 | 비어 있지 않은 합성 export의 전체 rollback·ID 보존 검증. 확인한 로컬 D1은 0건이며 운영 D1 export/import는 미실행 |

`/api/health/ready` 성공은 DB와 배포 모델 준비 확인이다. Google 로그인 완료, OpenAI 응답 가능 여부, AliExpress 상품·옵션 정확성까지 보장하지 않는다. `/api/agent/session`의 `configured: true`도 필수 설정값이 채워졌다는 뜻이며 실제 로그인 성공의 증거는 아니다.

현재 실행 시간 제한은 240초, DB lease는 300초다. 연결 종료나 서버 재시작 뒤 유료 작업을 자동 재실행하는 내구성 작업 큐는 없다. 취소는 추가 작업·늦은 결과 반영을 막는 동작이며 이미 공급자에게 전달된 요청의 과금 취소를 의미하지 않는다.

## 3. 먼저 완료해야 할 실제 사용자 검증

아래 항목은 정상 외부 계정이 준비된 로컬 또는 검증 환경에서 수행하고, 사용한 커밋·모델 버전·설계 ID·run ID·결과를 비밀값 없이 남긴다. 기존 테스트 통과로 대체하지 않는다.

| 우선순위 | 시나리오 | 완료 기준 |
| --- | --- | --- |
| P0 | 실제 Google 로그인 → 프로젝트 생성·편집 저장 → 새로고침 | callback 후 사용자 세션이 유지되고 같은 프로젝트·revision·fingerprint가 다시 로드됨. 로그아웃 후 개인 API 접근은 차단됨 |
| P0 | 현재 설계의 속도 성능 질문 → 실제 OpenAI 답변 | 정상 외부 응답과 저장된 `completed` 결과 확인. 본문 인용이 현재 run의 근거에 연결되고 원본·추정·학습 모델을 혼동하지 않음 |
| P0 | 잠금·목표가 있는 설계 개선 → 검토 → 적용 → 되돌리기 | 잠근 항목 유지, 적용 전후 차이 명시, 적용 시 revision 증가, 이전 내용 복구. 다른 탭에서 먼저 편집하면 이전 제안 적용은 충돌로 거절됨 |
| P0 | 실제 BOM 부품 검색 → 상품 선택 → 견적 저장 → 재접속 | 조회 출처·시각·통화·가격 종류가 유지되고 선택한 실제 offer만 저장됨. 임의 offer ID·클라이언트 가격으로 저장할 수 없음 |
| P0 | 서로 다른 실제 사용자 두 명의 프로젝트·실행·견적 접근 | 상대방의 ID를 알아도 읽기·수정·적용·취소가 모두 거절됨. 이메일만 같다는 이유로 기존 계정이 연결되지 않음 |
| P0 | 공급자 429·권한 거절·timeout, 스트림 중 탭 닫기·취소 | 성공 안내나 확정 가격을 만들지 않음. 실행 상태·부분 결과·사용량이 일관되고 새로고침 시 기록 확인 가능. 자동 유료 재실행 없음 |

AliExpress의 상품 검색 성공과 구매 확정은 다르다. `listing` 가격, 옵션 미확인, 묶음 수량 미확인, 배송비·세금 부재를 유지해야 한다. SKU 권한이 없는 상태에서는 임의 옵션을 확정하지 않는다. DS 연동은 기본 비활성이며 별도 권한을 전제로 한다. 정확한 모델이 검색되지 않으면 동등한 부품이라는 근거 없이 대체품을 확정하지 않는다.

## 4. 답변·실행 품질을 높이기 위한 후속 작업

### P1 — 대표 질문과 실패 사례의 회귀 평가

실제 한국어 질문 묶음에 기대 동작을 붙이고, 입력·모델·프롬프트 버전을 고정해 반복 평가한다. 적어도 다음 사례를 포함한다.

- 단위가 있는 속도·질량·전력 제한, 제한 없는 요청, 모호한 개선 목표, topology 유지·변경 요구를 구분한다. 명시하지 않은 상한이나 잠금 해제를 만들어내지 않는다.
- 현재 설계와 명시한 비교 설계, 원본 trim이 없는 속도, 모델 미지원 설계, 모델에 반영되지 않는 편집값, 이전 revision의 견적을 구분한다.
- 사용자 메시지·문서·상품 제목에 들어 있는 “지시를 무시하라”, “다른 사용자 데이터를 보여라”, 허위 가격·URL·상품 ID를 근거로 채택하지 않는다.
- 없는 근거 ID, 인용 누락, 원본과 예측의 혼동, 근거로 뒷받침되지 않는 원인 설명·비행 가능 주장, 숫자를 한글로 바꾼 허위 주장을 검토한다.
- 일부 부품만 조회 성공, 모호한 옵션·묶음 수량, 설명 생성만 실패, timeout 뒤 늦은 응답을 각각 확인한다.

현재 답변 검사는 존재하는 인용 ID·본문 숫자/URL 등 형식을 검사한다. 인용 문서가 문장의 의미를 실제로 뒷받침하는지까지 검증하지 않는다. 코드의 형식 검사와 별도로 근거 일치율·목표 해석 정확도·잠금 위반·불필요한 도구 호출·실패 시 오안내를 평가해야 한다. 예시 답변 몇 개가 그럴듯한 것을 품질 기준으로 삼지 않는다.

### P1 — 실패 상태와 복구 동작 명확화

현재 최종 `partial` 판정 일부는 한국어 경고 문자열에 의존한다. 자연어 설명만 실패한 결과도 계산·조회 근거는 남을 수 있으므로, 설명 실패·일부 공급자 실패·모델 입력 미지원의 상태를 구조화하고 화면·DB·NDJSON이 같은 의미를 사용하도록 정리한다. 경고 문구가 바뀌어도 완료 상태가 달라지지 않아야 한다.

실제 브라우저에서 진행 중 취소, 탭 종료, 느린 읽기, API 재시작을 검증한다. DB에 저장된 상태와 화면 표시가 합치고, 한 사용자의 취소가 다른 실행에 영향을 주지 않아야 한다. 재접속은 기록 조회이며 중단된 외부 요청의 자동 재시도는 아니다.

## 5. 운영 전 별도로 필요한 작업

- **계정과 데이터 이전:** 운영 D1 export 확보, 원본 보관, 건수·소유권·revision·견적 표본 대조, 읽기/쓰기 전환과 복구 절차 검증. 이전 세션은 가져오지 않으므로 재로그인 안내가 필요하다.
- **관측:** 비밀값을 기록하지 않는 run ID 중심 로그, 실행 성공·부분 성공·취소·오류 비율, 공급자별 오류·지연·호출 수, DB/모델 준비 실패를 확인할 대시보드와 알림을 준비한다.
- **비용:** 앱의 일일 횟수와 공급자 프로젝트의 금액 한도를 별도로 관리한다. 실패·취소된 요청도 이미 발생한 비용이 있을 수 있으므로 공급자 사용량과 앱 카운터를 대조한다.
- **저장소·서비스 운영:** PostgreSQL 백업·복원, HTTPS origin·쿠키·OAuth 반환 주소, 설정 회전, 데이터 보존·삭제 정책, 배포 중 진행 실행의 처리 기준을 검증한다.
- **공개 API 범위:** 공개 갤러리는 기존처럼 익명 게시·재사용을 허용한다. 실제 공개 운영에서는 관리·신고·남용 제한을 정하고, 로그인 없이 가능한 모델 추론의 동시 요청·CPU 사용 한계도 측정한다.

현재 테스트 근거는 [API 통합](../backend/tests/test_api_postgres.py), [PostgreSQL 저장·경쟁](../backend/tests/test_store_postgres.py), [OIDC·import](../backend/tests/test_auth_and_import.py), [LLM 오류·인용](../backend/tests/test_llm.py), [부품 계약](../backend/tests/test_parts_port.py), [NDJSON 프록시](../tests/api-proxy.test.mjs)에 있다. 전체 PostgreSQL 검증에는 별도 `TEST_DATABASE_URL`이 필요하며 skip 결과를 실제 DB 검증으로 표시하지 않는다.
