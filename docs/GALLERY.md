# 공유 갤러리

5단계의 `6단계 · 공유 갤러리 →` 버튼 또는 상단 6단계 탭으로 이동합니다.

- `내 설계 게시하기`: 현재 선택한 설계의 편집 내용, 부품, 형상, 전체 파라미터를 게시 시점의 복사본으로 저장합니다. 편집하지 않은 설계는 원본 shard에서 읽습니다.
- 제목, 제작자 닉네임, 사용목적, 설명과 복사·수정 허용 동의가 필요합니다.
- 갤러리에서 설계를 선택하면 실제 저장된 파라미터로 3D 미리보기를 표시합니다.
- `내 작업으로 가져오기`: 원본을 보존한 채 설계를 복사하고 2단계 편집기로 이동합니다. 현재 편집 내용이 있으면 교체 확인을 표시합니다.
- 가져온 설계를 다시 게시하면 원본 게시물의 링크를 보존합니다.
- 공유 링크 `/?gallery=<게시물 ID>`는 해당 게시물을 바로 엽니다. 최신 100개 게시물 검색, 사용목적 필터, 최신순/가져오기 횟수순 정렬을 지원합니다.

## 저장과 실행

`npm run dev`로 실행합니다. `vite.config.ts`의 `GALLERY_DB` D1 바인딩을 사용하며, API가 처음 호출될 때 테이블을 생성합니다. 개발 환경의 SQLite 데이터는 `.wrangler/state/v3/d1/`에 저장되므로 서버 재시작 후에도 유지됩니다. 게시물은 브라우저 저장소에 의존하지 않아 같은 서버에 접속한 다른 브라우저에서도 조회할 수 있습니다.

현재 편집 중인 작업은 브라우저의 `aerotwin-workspace-v1` 항목에 별도로 저장됩니다. 이 항목에는 설계 복사본과 가져온 원본 게시물 ID가 들어갑니다. 브라우저 저장소를 지우면 미게시 편집 내용은 사라집니다. 게시물 DB는 영향받지 않습니다.

서버 API: `GET /api/gallery`, `GET /api/gallery?id=<ID>`, `POST /api/gallery` (게시 또는 `action: reuse`). 서버에서 스냅샷 구조, 문자열 길이, 복사 허용 동의와 원본 ID를 검사하고 SQL 바인딩을 사용합니다. 저장 실패 시 성공으로 표시하지 않으며 게시 폼 입력은 유지됩니다.

## 공개 서비스로 배포할 때

현재는 실행 중인 개발 서버 범위에서 공유됩니다. `localhost` 주소는 다른 컴퓨터에서 직접 접근할 수 없으며 인터넷 배포는 아직 수행하지 않았습니다. 실제 공개 배포에는 D1 데이터베이스를 생성하고 `vite.config.ts`의 개발용 `GALLERY_DB` ID를 실제 ID로 교체해야 합니다. 개발 DB는 자동으로 배포 DB로 복사되지 않습니다.

현재 닉네임은 사용자가 입력한 표시 이름이며 계정 인증이나 제작자 소유권 검증은 없습니다. 공개 운영에 필요한 계정, 게시물 관리·신고, 요청 제한은 별도 범위입니다. 가져오기 횟수는 가져오기 요청 횟수이며 고유 사용자 수가 아닙니다.

공유 대상은 앱에서 편집 가능한 설계 스냅샷입니다. 3D는 파라메트릭 미리보기이고 제작용 CAD/STL 내보내기 또는 편집 후 성능 검증 결과를 제공하지 않습니다.
