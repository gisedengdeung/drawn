# 파라미터 편집 제출 계획

> 작성일: 2026-09-30  
> 제출 마감: **2026-10-01 19:00 (KST)**  
> 작업 브랜치: `parametric-functions-change`  
> 상태: P서버 개발 보류, 기존 뷰어 기반 편집 MVP 우선

## 1. 상황 변경

기존 계획은 플랜 A를 마감한 뒤 별도의 P서버를 설계·개발하는 것이었다.

```text
플랜 A 마감
  ↓
P서버 수직 슬라이스
  ↓
원본 STEP 기반 정밀 메시와 편집 메타데이터 제공
```

그러나 제출 마감이 2026년 10월 1일 19시로 변경됐다. 남은 시간 안에 P서버의
저장소, CAD 변환, 작업 큐, 메시 API, 캐시, 배포까지 구현하고 안정화하는 것은
현실적이지 않다.

따라서 이번 제출에서는 P서버를 구현하지 않고, 현재 플랜 A의 정적 STEP 요약본과
Three.js 뷰어를 유지한 채 **사용자가 이해하고 조작할 수 있는 파라미터 편집 MVP**를
완성한다.

P서버 계획은 폐기하지 않는다. 제출 이후 재개할 장기 구조로
`docs/PARAMETRIC_PLAN_B_HANDOFF.md`에 보존한다.

## 2. 이번 제출의 목표

이번 제출의 목표는 모든 CAD 형상을 자유롭게 편집하는 범용 설계기가 아니다.

다음 사용자 흐름을 안정적으로 보여주는 것이 목표다.

```text
설계 선택
  ↓
3D에서 편집할 구조 선택
  ↓
선택한 구조와 연결 부품 강조
  ↓
관련 파라미터만 표시
  ↓
길이·각도·오프셋·날개 치수 변경
  ↓
3D 형상에 즉시 반영
  ↓
초기 상태로 복원
```

핵심은 “슬라이더가 많다”가 아니라 사용자가 다음을 알 수 있게 하는 것이다.

- 지금 어떤 구조를 편집하고 있는가
- 어떤 부품들이 함께 움직이는가
- 어떤 값을 바꿀 수 있는가
- 변경 결과가 어디에 반영됐는가
- 언제든 원본 상태로 돌아갈 수 있는가

## 3. 제출 필수 범위

### 3.1 3D 선택과 편집 대상 연결

- 3D 부품을 클릭하여 편집 대상을 선택한다.
- 선택한 부품이 어느 팔, 날개, 추진 그룹에 속하는지 식별한다.
- 선택 대상과 함께 움직이는 연결 부품을 강조한다.
- 선택한 대상에 해당하는 편집 UI만 우선 표시한다.

예시:

```text
팔 2 클릭
  ├─ 팔 2 강조
  ├─ 팔 2의 관절 강조
  ├─ 연결된 모터·프로펠러 강조
  └─ 팔 2의 길이·각도·오프셋 UI 표시
```

### 3.2 팔 편집

- 팔 길이 변경
- 장착 각도 변경
- 결합 위치 오프셋 변경
- 부모 팔의 변경을 하위 관절·모터·프로펠러에 전파
- 무관한 형제 branch는 움직이지 않음

### 3.3 날개 편집

- span 변경
- root chord 변경
- tip chord 변경
- 편집 중 절차식 날개 형상으로 실시간 미리보기
- 편집 전 정확 메시가 있는 경우 원본 표시에 사용

### 3.4 선택 상태 시각화

- 선택 구조는 부품 종류별 색 또는 강조색으로 표시
- 선택하지 않은 부품은 흐리게 표시
- UI의 선택 대상과 3D 강조 대상이 일치
- 설계를 변경하면 잘못된 이전 선택 상태를 제거

### 3.5 복원과 안정성

- baseline 상태로 초기화
- 초기화 후 위치·회전·크기가 원본 편집 상태로 복귀
- NaN, Infinity, 음수 치수, zero-scale 메시를 생성하지 않음
- 설계를 바꿔도 설계 선택 필터 설정은 유지

## 4. 이번 제출에서 제외할 범위

다음 기능은 일정상 구현하지 않는다.

- P서버 구축
- 사용자 STEP 업로드와 서버 변환
- STEP/CAD 정밀 재생성
- 팔, 모터, 프로펠러, 날개 개수 추가·삭제
- 기존 topology 자체 변경
- 자유로운 부품 간 새 결합 생성
- 정밀 충돌 검사
- 모든 C/D등급 설계 수정
- 커뮤니티 저장·공유 시스템 개편
- 서버 기반 사용자 설계 버전 관리
- 복잡한 CAD 제약 조건 solver

특히 프로펠러 수 증가나 새로운 팔 추가는 단순한 숫자 변경이 아니다. 조립 구조,
부품 인스턴스, 연결 관계, 성능 입력을 동시에 바꿔야 하므로 이번 범위에서 제외한다.

## 5. 현재 기반 상태

플랜 A에서 다음 기반을 이미 만들었다.

- 27,714개 설계의 placement 기반 출력
- 설계 번호 검색
- 설계 선택 필터 상태 유지
- 원본 STL, 파라메트릭, 듀얼 뷰
- baseline과 draft 분리
- 선택 부품 강조와 비선택 부품 dimming
- 팔 길이·각도·오프셋 보정 구조
- assembly neighbour graph
- 부모에서 자식으로 이어지는 subtree 계산
- 모터·프로펠러 실제 메시 로딩
- 날개 span/root/tip 편집용 절차식 geometry
- 전체 형상 자동 감사 도구

최신 전체 형상 감사 결과:

```text
A      24,433
B       2,760
C         504
D          17
ERROR       0
평균 점수 96.89
```

이번 제출에서는 남은 D 17개를 더 고치지 않는다. 이들은 대부분 요약 데이터만으로
실제 날개 곡면과 스윕을 재구성하는 방식의 한계이며 편집 MVP와 직접 관련이 없다.

## 6. 구현 우선순위

### 1순위 — 기존 편집 기능의 실제 동작 확인

- 모든 표시된 슬라이더가 placement 경로에서 실제로 동작하는지 확인
- 편집값이 `draft`의 어느 필드를 바꾸는지 확인
- 편집 후 뷰어의 어느 부품에 적용되는지 확인
- 동작하지 않는 기능은 제출 전에 숨기거나 명확히 표시

### 2순위 — 선택 대상과 UI 연결

- Three.js picking 결과를 실제 부품 instance 이름으로 유지
- 부품 instance를 팔/날개/추진 그룹에 연결
- 선택 그룹에 필요한 UI만 펼치거나 상단에 배치
- UI에서 그룹을 선택해도 동일한 3D 강조 적용

### 3순위 — 연결 부품 변환 전파

- 부모 팔의 길이·회전을 descendant에 동일한 순서로 적용
- 모터와 프로펠러가 팔 끝을 따라 이동
- 형제 branch 격리
- 회전된 축을 렌더링 방향에도 반영

### 4순위 — 날개 편집 검증

- span, root chord, tip chord 변화 확인
- 좌우 대칭 날개의 편집 범위 확인
- 편집 전 실제 메시와 편집 후 미리보기 전환 확인
- 비대칭 NACA 익형의 윗면/아랫면 유지

### 5순위 — 초기화와 제출 검증

- reset round-trip
- 여러 설계를 연속 선택해 상태 누수 확인
- 원본/파라메트릭/듀얼 뷰 전환 확인
- 선택 강조와 카메라 조작 확인
- 대표 설계 화면 녹화 또는 스크린샷 준비

## 7. 시간이 부족할 때의 우선순위 축소

마감 전 모든 기능을 완성하지 못할 경우 다음 순서로 범위를 지킨다.

```text
반드시 유지
  1. 팔 길이 편집
  2. 연결 모터·프로펠러 이동
  3. 선택 그룹 강조
  4. reset

가능하면 유지
  5. 팔 각도와 오프셋
  6. 날개 span/root/tip 편집
  7. 선택 대상별 UI 축소

시간 부족 시 제외
  8. undo/redo 다단계 이력
  9. 키보드 기반 카메라 이동
 10. 고급 파라미터 전체 노출
```

작동하지 않는 기능을 여러 개 보여주는 것보다, 대표 편집 흐름 하나를 정확하고
안정적으로 보여주는 것을 우선한다.

## 8. 대표 검증 설계

최소 다음 유형을 검증한다.

- 단순 직선 팔 설계
- 꺾인 팔 설계
- branch/cross가 있는 설계
- 서로 다른 길이의 팔이 있는 설계
- 날개가 있는 설계
- 모터·프로펠러 실제 메시를 사용하는 설계
- #11654: 설계 전용 정확 메시와 편집 전환 확인
- #7266: root/tip 시위가 역전된 날개 확인
- #13870: 여러 날개 그룹 binding 확인
- #25255: 비대칭 익형의 좌우 방향 확인

대표 설계는 모든 데이터 유형을 증명하기 위한 fixture이며, 해당 설계에만 동작하는
예외 코드를 추가하기 위한 목록이 아니다.

## 9. 제출 완료 기준

다음 조건을 만족하면 제출 가능한 상태로 본다.

- 사용자가 3D에서 편집할 구조를 선택할 수 있음
- 선택한 구조와 연결 부품이 명확히 강조됨
- 관련 없는 편집 UI 때문에 대상을 혼동하지 않음
- 팔 길이 변경 시 뿌리는 유지되고 바깥쪽 부품만 이동
- 부모 회전 시 descendant 위치와 방향이 함께 변경
- 형제 branch는 움직이지 않음
- 날개 치수 편집이 화면에 즉시 반영
- reset 후 baseline 상태로 복귀
- 설계 전환과 뷰 전환 후 빈 화면이나 런타임 오류가 없음
- 타입 검사와 변경 파일 lint 통과
- 알려진 제한 사항이 제출 문서에 기록됨

## 10. 제출 시 설명할 제한 사항

현재 편집기는 STEP 원본을 직접 수정하는 CAD 편집기가 아니다.

- STEP 요약본과 placement를 기준으로 Three.js 형상을 편집한다.
- 이동·회전·치수 변경을 실시간 미리보기로 제공한다.
- 구멍, 곡면, 정밀 결합부의 CAD 재생성은 지원하지 않는다.
- topology 추가·삭제는 지원하지 않는다.
- 원본과 완전히 동일한 메시 기반 재생성은 향후 P서버 단계에서 처리한다.

이 제한을 숨기지 말고, 이번 제출은 **파라메트릭 편집 인터랙션과 조립 전파 구조를
검증하는 MVP**라고 설명한다.

## 11. 제출 이후 계획

제출 이후에는 `docs/PARAMETRIC_PLAN_B_HANDOFF.md`를 기준으로 다음 작업을 재개한다.

1. 대표 STEP 10~20개의 P서버 수직 슬라이스
2. 부품별 정확 메시와 콘텐츠 hash 생성
3. 조립·결합 메타데이터 API
4. 브라우저 로컬 미리보기와 서버 정밀 재생성 연결
5. 사용자 설계 저장·공유
6. 기존 27,714개 설계의 점진적 마이그레이션

이번 제출 코드가 버려지지 않도록 편집 명령, 선택 그룹, assembly subtree 개념은
P서버에서도 재사용 가능한 형태로 유지한다.
