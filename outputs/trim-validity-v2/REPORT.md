# Trim 유효성 재학습 결과

**재학습 및 ONNX 검증 완료. UI용 개선 목표는 아직 달성하지 못했다.**
상한 과대예측은 감소했지만 recall과 F1이 떨어졌고, 속도 집합 완전 일치는
개선되지 않았다. 모든 속도가 무효인 설계에 유효 속도를 하나라도 예측하는
설계 단위 오탐은 오히려 증가했다. 기존 모델을 대체할 후보로 추천하지 않는다.
산출물은 비교·후속 실험용으로 보관한다.

## 같은 코드로 비교한 최종 테스트

손상 행 50개를 제외한 동일 관측 셀 기준이다. 테스트 설계는 2,724개이며,
관측된 양성 속도가 있는 설계는 878개다. 기존 모델 임계값은 기존 평가에서
검증셋으로 정한 0.79, 재학습 후보는 이번 검증셋으로 정한 0.55다.
임계값과 모델 선택을 고정한 뒤 테스트를 한 번 평가했다.

| 지표 | 기존 v1 | 재학습 후보 |
| --- | ---: | ---: |
| 속도 행 precision | 61.59% | 65.45% |
| 속도 행 recall | 74.73% | 64.93% |
| 속도 행 F1 | 0.6753 | 0.6519 |
| 활성 설계의 속도 집합 완전 일치 | 22/878 (2.51%) | 22/878 (2.51%) |
| 활성 설계의 상한 과대예측 | 274/878 (31.21%) | 138/878 (15.72%) |
| 활성 설계의 평균 속도 집합 IoU | 0.5195 | 0.5070 |
| 전 속도 무효 설계의 거짓 유효 판정 | 237/1845 (12.85%) | 379/1845 (20.54%) |

상한 과대예측의 분모는 실제 유효 속도가 하나 이상 있는 설계 전체다.
유효 속도를 아예 예측하지 않은 경우에는 상한 과소예측으로 센다.
연속 구간을 강제하지 않으며, 유효 속도 사이의 무효 구멍도 그대로 평가한다.

원래 라벨을 유지한 legacy 평가의 F1은 **0.675192 → 0.651556**이다.
전달받은 기존 F1 0.6752는 재현됐다. 다만 전달받은 완전 일치 38/879 및
상한 과대예측 41%는 로컬 체크포인트와 기존 임계값 0.79로 재현되지 않았다.
이 조합에서는 22/879와 274/879다. 원인을 단정하지 않으며,
임계값 0.5 결과 및 같은 새 선택 정책을 적용한 v1 결과도 JSON에 함께 남겼다.
다른 평가 코드·대상 집합과 비교할 때 이 차이를 먼저 확인해야 한다.

## 학습과 선택

- RTX 5070 Ti 16GB, PyTorch 2.13.0+cu130, Python 3.13.9.
- 원본 데이터: 27,714개 설계 × 1,024개 XYZ 점. family 고정 분할 유지.
- 학습 22,187 / 검증 2,803 / 테스트 2,724개 설계.
- 선택 과정에 새로운 테스트 점수는 사용하지 않았다. 다만 기존 테스트 분석이
  이번 요청의 출발점이므로 완전히 처음 보는 holdout이라고 주장하지 않는다.
- 기존 코드도 이미 양성 가중치 약 7.54와 분류 계수 0.25를 사용했다.
  이번에는 분류 경로를 분리하고 BCE 가중치 1 또는 제곱근 가중치,
  설계별 Tversky 집합 손실, 상한 위 오탐 손실을 비교했다.
- 동결한 형상 특징을 사용하는 분류 헤드 4개와, 별도 PointNet 인코더까지
  학습하는 후보 2개, 총 6개 유효성 실험을 수행했다.
- 최종 비교 후보: **set_fp / epoch 5 / threshold 0.55**.
  BCE 양성 가중치 1, 집합 손실 계수 0.5, 상한 오탐 손실 계수 0.25.
  집합 손실은 FP 0.7 / FN 0.3 Tversky이며 비연속 속도 집합을 허용한다.
- 검증 선택은 F0.5·활성 설계 IoU·정확 집합 일치·설계 recall·상한 오탐을
  함께 사용하고, 속도 recall ≥ 0.6356 및 설계 recall ≥ 0.70을 요구했다.
  원래 회귀 점수와 F1을 결합한 선택 규칙과는 다른 보수적 실험 기준이다.
- 별도 분류용 인코더 학습은 선택 점수를 더 개선하지 못해 채택하지 않았다.

## 회귀 및 호버 정제

기존 회귀 6개는 **가중치와 실제 예측값 모두 그대로 유지**된다.
검증·테스트 예측의 최대 절대 차이는 0이다. 호버 손상 행을 제외하고 실제
Mass×g를 약한 학습 손실(계수 0.02)로 넣는 회귀 헤드 미세조정도 실행했으나,
검증 성능 보존 조건을 만족하지 못해 채택하지 않았다.
정제된 라벨로 계산한 회귀 점수 변화는 평가 대상 변화이며 모델 개선이 아니다.

호버 제외 규칙은 속도 0에서 다음 조건을 모두 요구한다.

1. drag가 유한하지 않음.
2. maxUc가 정확히 0.5.
3. Mass가 유한한 양수이고 thrust < 0.5×Mass×9.80665.

그 실패 호버 행과 **거리 이외의 11개 열이 NaN 위치까지 정확히 같은 복제 행**도
제외했다. 다른 속도에서 thrust/Mass 비율만으로 제외하지 않는다.
원본 라벨과 원본 NPZ는 수정하지 않았으며, 별도의 관측 마스크로 분류·회귀
손실에서 제외했다. 손상된 행을 음성 라벨로 바꾸지 않았다.

- 총 202행: 학습 152 / 검증 0 / 테스트 50.
- 학습 설계: 664(1행), 11508(1행), 17287(50행), 22875(50행), 25568(50행).
- 테스트 설계 20015: 속도 0–49의 50행 제외. 속도 50의 원래 무효 라벨은 유지.
- 20015처럼 일부 음성만 관측되고 나머지는 미확정인 설계는, 설계 전체가
  무효라고 단정하는 지표의 분모에서 제외했다.

## 팀 공유: 기각된 Mass 앵커링

수신자가 이미 수행한 실험: 예측 Mass 앵커링은 thrust MAE를 **3.22 → 6.52 N**으로
악화시켰다. 실제 Mass를 쓰면 1.25 N으로 좋아졌지만, 예측 Mass가 부정확하므로
추론 후처리로 반복 적용하지 않는다. 이번 작업에서도 예측 Mass 앵커링은 사용하지 않았다.
위 수치는 이번에 다시 측정한 값이 아니라 전달받은 선행 실험 결과다.

## 산출물과 검증

- `runs/selected.pt`: 비교 후보 체크포인트.
- `onnx/trim-encoder-v2.onnx`: 582,764 bytes.
- `onnx/trim-head-v2.onnx`: 4,513,316 bytes.
- `onnx/manifest.json`, `onnx/test_vectors.json`: 체크섬·입출력·검증 벡터.
- `evaluation/comparison.json`: 검증/테스트, 원래/정제 라벨, 양 모델의 전체 비교.
- `evaluation/test_predictions.npz`, `evaluation/test_speed_sets.csv`: 행별 검토 자료.
- `data/hover_audit.json`, `data/hover_supervision_masks.npz`: 손상 행 근거와 마스크.
- `runs/selection.json`, 각 실험 JSON 및 학습 로그: 선택 근거와 학습 이력.
- `source/ml/`: 재현용 코드와 테스트. 원본 학습 소스는 git `745f00c`에서 복원.
- `environment.json`, `EXPERIMENT_PLAN.md`: 환경과 사전 고정 실험 정책.

ONNX PyTorch 대조·동적 배치·속도 길이·점 순서 불변성 **56개 검사 통과**.
속도 길이 1/5/51과 소수 속도 0.5/13.25/49.75도 검증했다.
별도 수신자 검증기 결과 **VERIFIED**, 단위 테스트 **22개 통과**.
최종 후보의 특징 차원은 기존과 같은 2049이며 encoder/head를 한 쌍으로 사용한다.
정수 속도 0–50에서 학습했고 소수 속도 유효성은 인접 로짓을 보간한다.
ONNX 일치는 수치·실행 호환성 검증이며 예측 정확도 개선을 뜻하지 않는다.

저장소 루트에서 수신자 검증:

```powershell
outputs\trim-validity-v2\.venv\Scripts\python.exe outputs\trim-validity-v2\source\ml\verify_onnx_trim.py --manifest outputs\trim-validity-v2\onnx\manifest.json
```

후속 작업에서는 상한 오탐만 줄이는 점수로 새 모델을 채택하지 말고,
속도 recall·정확 집합 일치·전 속도 무효 설계의 오탐에 각각 허용 조건을
정하는 것이 필요하다. 이번 테스트 결과로 추가 튜닝은 하지 않았다.
